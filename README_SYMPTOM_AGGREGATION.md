# 🧠 RAG_Evaluate_WholeReport 症状聚合系统

## 🎯 系统核心概念

这个系统**不是**逐个处理症状，而是采用**症状聚合**的方法：

### 🔄 症状聚合流程

1. **症状聚合** → 将同一报告的所有症状合并成一个整体文本
2. **整体预测** → LLM基于聚合症状直接预测器官和位置
3. **智能分割** → LLM将聚合症状重新分割成小的症状单元
4. **RAG搜索** → 基于LLM分割的症状进行知识库搜索

### 📊 两种处理模式

#### 模式1: 症状聚合基线方法
- 症状聚合 → 整体预测 → 智能分割 → RAG搜索
- 每个报告只需1次API调用进行整体预测

#### 模式2: 增强症状聚合方法
- 症状聚合 → 整体预测 → 智能分割 → 增强RAG搜索
- 更智能的症状分割和更深入的RAG分析

## 🔍 工作流程详解

### 步骤1: 症状聚合基线方法
```
原始症状: [症状1, 症状2, 症状3, ...]
    ↓
聚合症状: "症状1; 症状2; 症状3; ..."
    ↓
LLM整体预测: 器官和位置
    ↓
LLM智能分割: 重新识别症状单元
    ↓
RAG搜索: 基于分割症状的知识检索
```

### 步骤2: 增强症状聚合方法
```
症状聚合 → 整体预测 → 智能分割 → 增强RAG搜索
    ↓
更智能的症状分割逻辑
    ↓
更深入的医学知识检索
    ↓
更准确的器官定位分析
```

### 步骤3: 对比分析
```
对比两种方法的:
- 症状聚合效果
- 整体预测准确性
- 智能分割质量
- RAG搜索相关性
```

## 💡 核心优势

1. **效率提升**: 每个报告只需1次API调用，而不是每个症状1次
2. **症状关联**: 考虑症状间的相互关系，提高诊断准确性
3. **智能分割**: LLM自动识别和分割症状，而不是人工预设
4. **知识增强**: 基于智能分割症状进行RAG搜索，获得更精准的医学知识

## 📁 输出结果

- `baseline_results/`: 症状聚合基线方法结果
- `aggregation_results/`: 增强症状聚合方法结果
- `comparison_results/`: 两种方法对比分析结果

每个结果包含：
- 聚合症状文本
- 整体器官预测
- 智能分割的症状单元
- RAG搜索的医学知识
- 处理时间戳和元数据

## 🔧 技术架构

- **症状聚合器**: 将多个症状合并为单一文本
- **整体预测器**: LLM基于聚合症状进行器官定位
- **智能分割器**: LLM重新识别和分割症状单元
- **RAG搜索器**: 基于分割症状进行知识库检索
- **对比分析器**: 评估两种方法的性能差异

这个系统代表了**医学AI症状分析的新范式**，通过症状聚合和智能分割，实现了更高效、更准确的医学诊断支持。
